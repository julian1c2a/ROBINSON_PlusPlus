## 0. Scope, method and caveats

- **Repos.** FOL was at `782928c` when the run started. During the run HEAD moved to `1df51b3` (another session, ADR-128). That commit changed only `lakefile.lean` and `DECISIONS.md` and no `.lean` module, so every line number below is still valid. RPP is at `8fd14f4`; another session has uncommitted edits there (`DECISIONS.md`, `NEXT-STEPS.md`, `lakefile.lean`). I did not touch either repo.
- **Method.**
  - I ran `LC_ALL=C awk -f FOL/strip-lean.awk` on every module in the build: `FOL.lean`, the 49 files under `FOL/**` (all reachable from `FOL.lean`) and the 6 under `TheoryFramework/**`. Its output keeps only code.
  - To find literals in code, I ran a variant of the stripper through process substitution (`awk -f <(sed 's/out = out " "; tb = tb "\\""/out = out "@@L@@"; …/' strip-lean.awk)`). It marks each literal instead of deleting it.
  - No file was written. lake, lean, elan and leanchecker were not run, so every "compiles" claim below is an ESTIMATE.
- **Site classes.**
  - **TYPE**: rename `String` → `List Char`. A † means the type is an argument and needs parentheses.
  - **LITERAL**: `"X"` → `['X']`.
  - **API**: needs redesign.
  - **PROOF**: the proof uses a `String` lemma or `String.decEq`.
  - **KDEC**: a proof that computes symbol equality in the kernel (`decide`/`rfl`) with no String lemma named. It should keep working; it must be re-checked by a build.
  - **PRINT**: printing or syntax only, no change.

## 2. API redesign

### 2.1 `FOL/FOL.lean`

```lean
abbrev Term := TermG (List Char)                                          -- :69
abbrev Formula := FormulaG (List Char)                                    -- :70
  TermG.noConfusion (S := List Char) (S' := List Char) rfl (heq_of_eq h)     -- :80
  FormulaG.noConfusion (S := List Char) (S' := List Char) rfl (heq_of_eq h)  -- :91
-- :122-124  instance : Coe String Formula  → DELETE (recommended)
  .impl (.atom ['P'] []) (neg (neg (.atom ['Q'] [])))                     -- :342
  replaceAt formula_ejemplo posicion_Q (.atom ['Q'] [])                   -- :350
```

Why delete the coercion rather than retarget it:
- It has zero users in FOL (MEASURED).
- A `Coe (List Char) Formula` would silently turn any symbol into an atom wherever a Formula is expected. During the migration that hides type errors.
- Keeping `Coe String Formula` through `String.toList` would keep both String and UTF-8 decoding in FOL.

An optional convenience is a `sym!"P"` macro that expands to `['P']` at elaboration time. It would add a meta-level constant, so it belongs in `Tactics.lean` (which already imports `Lean`), not in `FOL.FOL`.

`deriving Repr, BEq` and `DecEq.lean`'s `[DecidableEq S]` are generic and need no change. `instDecidableEqList` and `instDecidableEqChar` (Init/Prelude.lean:2883, :2982) reduce structurally.

### 2.6 Duplicate `FreshSym (List Char)` instance

After §2.3 the tree would hold two different `FreshSym (List Char)` instances: `FOL.instFreshSymListChar` (SymClasses, with `cst n = 'c' :: replicate n 'i'`) and Fresh0's. Lean accepts this, but which `cst` a future consumer gets would depend on its imports.

- **Option A (recommended).** Keep Fresh0's instance and delete SymClasses.lean:97–114. The class is then witnessed by the very definitions the completeness chain uses.
- **Option B (fewest row edits).** Keep SymClasses' instance and delete Fresh0.lean:149–158.
- Either way, the "two inhabitants" claim at SymClasses:97–99 becomes false.
- Recommendation: also drop `EnumSym String` (§2.5). Keeping String instances keeps String API in FOL, which conflicts with the D7 closing criterion.
