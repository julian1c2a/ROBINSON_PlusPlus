const REVIEW_SCHEMA = {
  type: 'object',
  properties: {
    problems: {
      type: 'array',
      items: {
        type: 'object',
        properties: {
          file: { type: 'string' },
          line: { type: 'integer' },
          problem: { type: 'string', description: 'qué está mal en lo editado HOY (falso según el código, cita [B] muerta, cifra sin medir, estilo, marca de cabecera mal, corrección confirmada que no se aplicó)' },
          evidence: { type: 'string' },
          fix: { type: 'string', description: 'el texto exacto que debería ir' },
          severity: { type: 'string', enum: ['alta', 'media', 'baja'] },
        },
        required: ['file', 'line', 'problem', 'evidence', 'fix', 'severity'],
      },
    },
    summary: { type: 'string' },
  },
  required: ['problems', 'summary'],
}

const out = await pipeline(
  GRUPOS,
  (g) => agent(`${REGLAS}

TUS FICHEROS: ${g.files} (rutas relativas a ${RPP}).
${g.extra}

TUS DATOS están en el fichero JSON ${DATOS}/${g.key}.json (léelo ENTERO con la herramienta Read): un objeto con
- "confirmed": las CORRECCIONES CONFIRMADAS (file, line, quote, confirmed, reason, fix): las que aplicas (regla 2);
- "rejected": las que el verificador RECHAZÓ: NO las apliques; están para que no las repitas;
- "missing": controles reales que el documento, si pretende enumerarlos, no nombra: añade sólo lo que encaje y sea cierto.
Si no puedes leer ese fichero, NO edites nada y dilo.`, { label: `aplicar:${g.key}`, phase: 'Aplicar' }),
  (informe, g) => agent(`Repositorio: ${RPP} (Lean 4; español). HOY 2026-10-31. Eres un REVISOR ESCÉPTICO de T21: otro agente
acaba de editar ${g.files} para corregir lo que esos documentos decían mal de los controles del proyecto. NO EDITES NADA:
sólo lee y busca problemas en lo editado hoy. Mira el diff con «git -C ${RPP} diff -- <fichero>» (los cambios de hoy, sin
commitear; algunos de otro trabajo de hoy —las marcas «**Last updated:**» de T24 y la sección [E] del script— no son de
este agente, pero revísalos igual si caen en tus ficheros).
Para CADA hunk: (a) ¿lo que dice es CIERTO según el código (.github/workflows/build.yml, los scripts check-*.bash,
scripts/*)? Compruébalo leyendo el código; (b) ¿hay algo entre comillas invertidas que NO sea una constante de Lean, un
módulo o la ruta de un fichero versionado (git ls-files) de RPP o de FOL? (el control [B] lo daría por cita muerta; las
opciones, herramientas, flags y cosas de git van en texto plano); (c) ¿una cifra nueva sin un control que la mida?;
(d) ¿la marca de cabecera está bien? (PLAN-PRUEBAS, WORKFLOW, README y CURRENT-STATUS: «**Last updated:** 2026-10-31 — …
Antes, …» con la cadena anterior intacta; AI-GUIDE y .claude/commands/docsync.md: su fecha NO cambia); (e) ¿se dejó sin
aplicar alguna corrección confirmada sin decir por qué? Si tocó check-doc-sync.bash: sólo comentarios y textos, y
«bash -n» limpio. El informe del editor fue:
${informe}`, { label: `revisar:${g.key}`, phase: 'Revisar', schema: REVIEW_SCHEMA }).then(r => ({ grupo: g.key, informe, revision: r })),
)
return out.filter(Boolean)
